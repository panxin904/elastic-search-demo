# CDN 分发架构

<span class="kg-badge kg-badge-protocol">架构</span>
<span class="kg-badge kg-badge-app">直播</span>
<span class="kg-badge kg-badge-cases">案例</span>

**CDN** = Content Delivery Network，将视频内容**就近分发**到用户，提升体验、降低延迟。

## 🏗️ 直播 CDN 架构

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  推流端 (主播)         CDN 中心                拉流端    │
│  ┌──────────┐      ┌─────────────┐         ┌────────┐   │
│  │ OBS /    │      │             │         │ 用户A  │   │
│  │ FFmpeg   │ RTMP │   中心节点   │  HLS    │ 用户B  │   │
│  │ 手机     │ ───→ │   (转码)    │ ──────→ │ ...    │   │
│  └──────────┘      │             │         └────────┘   │
│                    └──────┬──────┘                       │
│                           │ 分发                         │
│                    ┌──────┴──────┐                       │
│                    │             │                       │
│              ┌─────┴──┐    ┌─────┴──┐                    │
│              │边缘节点│    │边缘节点│                    │
│              │ 北京   │    │ 上海   │                    │
│              └───┬────┘    └────┬───┘                    │
│                  │ HLS / RTMP  │                        │
│                  ▼             ▼                        │
│              北京用户      上海用户                      │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

## 📐 直播 CDN 关键组件

| 组件 | 作用 |
| --- | --- |
| **推流节点** | 接收推流（RTMP/SRT） |
| **转码集群** | 多码率、转封装 |
| **中心节点** | 调度、分发 |
| **边缘节点** | 就近覆盖用户 |
| **回源** | 边缘 → 中心 |
| **调度系统** | DNS / 302 / HTTPDNS |

## 📐 协议分层

```
直播:
  推流: RTMP / SRT / WHIP (WebRTC)
  分发: RTMP / HLS / DASH / LL-HLS
  播放: HLS / WebRTC

点播:
  分发: HLS / DASH
  播放: HLS / DASH
  加速: HTTP 缓存
```

## 📊 直播工作流程

```
1. 推流
   主播 RTMP → 推流节点

2. 转码
   推流节点 → 转码集群（多码率 + 多协议）

3. 分发
   转码集群 → 中心节点 → 边缘节点

4. 播放
   边缘节点 → 用户（最近节点）

5. 录制
   录制节点 → 对象存储（点播）
```

## 📐 调度策略

### DNS 调度

```
用户请求 video.com/live.m3u8
  ↓
DNS 查询
  ↓
返回最近边缘节点 IP
  ↓
连接到该边缘
```

### HTTP 302 调度

```
用户请求 video.com/live.m3u8
  ↓
中心返回 302 → best.edge.com/live.m3u8
  ↓
连接到 best.edge.com
```

### HTTPDNS 调度

```
解决 DNS 劫持、精准调度
客户端 SDK 直接调用 HTTPDNS API
获取最近边缘 IP
```

## 📊 边缘节点类型

| 类型 | 特点 |
| --- | --- |
| **L1 边缘** | 一线城市，回源频繁 |
| **L2 边缘** | 二三线城市，回源 L1 |
| **下沉边缘** | 运营商内，更近用户 |

## 📐 直播 + CDN 优化

| 优化 | 说明 |
| --- | --- |
| **多 CDN 备份** | 主备 CDN，故障切换 |
| **GZIP / Brotli** | 文本压缩 |
| **HTTP/2** | 多路复用 |
| **HTTP/3 (QUIC)** | 减少握手 |
| **边缘转码** | 边缘节点转码 |
| **预热** | 提前缓存到边缘 |
| **预拉** | 客户端预拉下一段 |

## 📊 点播 CDN 优化

```
1. 分层缓存
   边缘 → 中心 → 源站

2. Range Request
   支持断点续传

3. Cache-Control
   边缘缓存策略

4. 预热 / 预拉
   提前推送热点

5. 多副本
   跨地域冗余
```

## 📐 转码集群架构

```
推流节点
  ↓
[负载均衡]
  ↓
┌─────┬─────┬─────┐
│转码机│转码机│转码机│  ← 各转多码率
└─────┴─────┴─────┘
  ↓
[消息队列] Kafka
  ↓
[录制 + 对象存储]
  ↓
CDN 分发
```

## 📐 容灾设计

| 故障 | 应对 |
| --- | --- |
| **主播断流** | 重连、自动续推 |
| **推流节点故障** | 切换备用推流 |
| **转码故障** | 任务重试、备用实例 |
| **边缘故障** | 调度到备用边缘 |
| **CDN 整体故障** | 多 CDN 备份 |
| **录制失败** | 重试、转存 |

## 📊 成本控制

```
CDN 成本组成:
  - 流量费（按 GB）
  - 转码费（按分钟）
  - 存储费（按 GB/月）
  - 请求费（按万次）

优化:
  - 降低码率（H.265 节省 30%）
  - 适当切片（减少请求）
  - 边缘缓存（减少回源）
  - 限速防刷
```

## 📌 面试考点

1. 直播 CDN 如何调度？
   - DNS / 302 / HTTPDNS
2. 边缘节点和中心节点区别？
   - 边缘就近用户；中心汇聚 + 转码
3. HLS 在 CDN 上的优势？
   - HTTP 缓存友好，分段独立
4. 多 CDN 怎么用？
   - 主备、负载均衡、智能调度

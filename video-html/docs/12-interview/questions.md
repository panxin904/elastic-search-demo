# 视频处理高频面试题

音视频岗位面试覆盖 **理论原理 + 工程实践 + 性能调优 + 系统设计**。

## 🎬 一、视频基础

### Q1. 视频是什么？

A: 视频 = **连续的静态图像 + 音频** 组合。

- 一段动画 / 视频每秒 24-60 张图（帧）
- 每帧 ≈ 一张图像
- 通过显示设备以一定帧率播放，形成连续运动的错觉

### Q2. 视频文件结构？

A: 视频文件 = **容器 + 流**。

- **容器**（MP4 / MKV）：包裹格式，存信息
- **流**（Stream）：实际的视频 / 音频 / 字幕数据
- **元数据**：分辨率、码率、时长、编码格式等

### Q3. 颜色空间：YUV 和 RGB？

A:
- **RGB**：红绿蓝，每个分量独立，便于显示
- **YUV**：亮度 Y + 色度 U/V，人眼对亮度敏感，可降低色度采样
- 视频传输用 YUV（420 / 422 / 444）
- 显示器输出用 RGB

### Q4. YUV 4:2:0 / 4:2:2 / 4:4:4？

A: 色度采样方式：
- **4:4:4**：YUV 完整采样，无压缩
- **4:2:2**：U、V 水平方向 2:1 采样
- **4:2:0**：U、V 水平和垂直都 2:1 采样（H.264/H.265 默认）

### Q5. 什么是 GOP？

A: Group of Pictures，关键帧组：
- 两 I 帧之间的所有帧组成 GOP
- 短 GOP（直播）= 快速 seek
- 长 GOP（点播）= 更高压缩率

### Q6. 什么是 IDR？

A: IDR = Instantaneous Decoding Refresh，关键帧。
- 解码重置点
- 重新建立 DPB（参考帧列表）
- 不可被其他帧参考

## 🧮 二、编码原理

### Q7. 帧间预测原理？

A: 利用 **时间冗余**：
- 当前帧 ≈ 上一帧 + 偏移（运动矢量）
- 残差（residual）= 当前帧 - 预测
- 只编码残差 + 运动矢量

### Q8. 帧内预测？

A: 利用 **空间冗余**：
- 当前块 ≈ 邻块
- 9 种（H.264） / 33+ 种（H.265）预测模式
- 选最优模式 + 编码残差

### Q9. DCT 变换为什么要 8x8？

A:
- 8x8 是 1990s 主流硬件计算效率最优解
- 块太大 → 计算复杂
- 块太小 → 频域不集中
- 现代编码（H.265）= 4x4 ~ 64x64 DCT

### Q10. 量化是什么？

A: 量化 = **降低残差系数精度**：
- 高频系数大幅量化（甚至置 0）
- 用于码率控制
- QP 越大 → 越严重 → 画质越差

### Q11. CABAC 与 CAVLC？

A:
- **CAVLC**：变长码，可配置表，编码简单
- **CABAC**：算术编码 + 上下文，压缩率比 CAVLC 高 5-15%
- H.264 两种都可选；H.265 只用 CABAC

### Q12. 运动估计搜索算法？

A:
- **全搜索（FS）**：枚举所有位置，最优但最慢
- **三步法（TSS）**：粗搜索 → 精搜索
- **菱形（DS）**：六边形 / 菱形模板
- **EPZS / TZSearch**：H.265 默认
- **光流法（OFM）**：基于光学流

### Q13. RDO（率失真优化）？

A: 编码时选择最优模式：
\[
J = D + \lambda \times R
\]
- D：失真（与原图差距）
- R：码率
- λ：拉格朗日因子
- 通过遍历模式，选择 J 最小

## 📺 三、标准对比

### Q14. H.264 / H.265 / AV1 核心区别？

| 维度 | H.264 | H.265 | AV1 |
| --- | --- | --- | --- |
| **发布时间** | 2003 | 2013 | 2018 |
| **压缩率** | 基准 | -50% | -60% |
| **专利** | 收费 | 收费 | 免费 |
| **复杂度** | 中 | 高 | 极高 |
| **硬件支持** | 广泛 | 广泛 | 发展中 |

### Q15. AV1 优势？缺点？

优势：
- **免专利费**（开放编码）
- 比 H.265 压缩率高 20-30%
- YouTube / Netflix 已大规模采用

缺点：
- **编码复杂度高**（10x H.265）
- 硬件解码仍在推进
- 软解 CPU 占用高

### Q16. 为什么 H.265 仍常用？

A:
- 硬件解码普及（手机 / 电视 / 显卡）
- 兼容性最好
- 专利池运营成熟
- AV1 硬件仍在普及中

## 🔧 四、FFmpeg 实战

### Q17. FFmpeg 是什么？

A:
- 跨平台多媒体处理工具
- libavcodec / libavformat / libavfilter / libavutil / libavdevice / libswscale / libswresample
- 包含 ffmpeg / ffprobe / ffplay

### Q18. ffmpeg 转码命令？

```bash
ffmpeg -i input.mp4 -c:v libx264 -preset medium -crf 23 -c:a aac -b:a 128k output.mp4
```

参数：
- `-i` 输入
- `-c:v` 视频编码器
- `-preset` 速度预设
- `-crf` 质量参数（18-28）
- `-c:a` 音频编码器

### Q19. 提取视频中第 5 秒的帧？

```bash
ffmpeg -i input.mp4 -ss 5 -frames:v 1 cover.jpg
```

### Q20. -ss 位置差异？

```bash
# 关键帧解码 - 精确（默认）
ffmpeg -ss 5 -i input.mp4 ...

# 解码前 seek - 快但不准
ffmpeg -i input.mp4 -ss 5 ...

# 输入前（精准 + 快）
ffmpeg -ss 5 -i input.mp4 -c:v libx264 output.mp4
```

### Q21. 如何降低延迟？

A:
1. preset = ultrafast / 低延迟
2. tune = zerolatency
3. 禁用 B 帧（bf=0）
4. 短 GOP（g=60）
5. 关闭 lookahead
6. 硬编优先（NVENC / VideoToolbox）

### Q22. 音视频同步？

A: 三种方式：
- **同步到音频**（默认）：播放时钟 = 音频时钟
- **同步到视频**：以视频时钟为准
- **同步到外部**：手动指定 master clock

FFmpeg 中的 AVFrame `pts` 控制播放时机。

## 🚀 五、性能优化

### Q23. NVENC 加速？

A: 利用 **NVIDIA GPU** 独立编码芯片：
- 单卡并发 8-16 路 1080p
- 速度比 libx264 CPU 编码快 5-20 倍
- 实时直播首选

### Q24. 多线程并行？

A:
- FFmpeg `-threads n`
- x264 帧级 + slice 级
- x265 WPP（波前并行）
- 解码端硬件多 session

### Q25. 优化转码速度？

```bash
# 方案
ffmpeg -i input.mp4 \
  -c:v h264_nvenc \     # 硬编
  -preset ll \          # 低延迟
  -rc vbr \             # 动态码率
  -b:v 4000k \
  -c:a aac \
  output.mp4
```

## 📡 六、流媒体

### Q26. RTMP / HLS / WebRTC 区别？

| 协议 | 延迟 | 用途 |
| --- | --- | --- |
| **RTMP** | 1-3s | 主播推流、传统直播 |
| **HLS** | 5-30s | 点播、大规模直播 |
| **WebRTC** | < 500ms | 互动、低延迟直播 |

### Q27. HLS 切片原理？

A: HLS = HTTP Live Streaming
- 切片（segment.ts）：每个 4-10s
- 主清单（master.m3u8）
- 子清单（variant playlist）
- 客户端选择清晰度

### Q28. 自适应码率（ABR）算法？

A: 客户端根据缓冲区、网络切换清晰度。
- **BOLA**：基于缓冲区
- **MPC**：基于模型预测
- **Pensieve**：基于强化学习

## 🤖 七、AI 应用

### Q29. AI 超分辨率原理？

A: 用 **深度神经网络** 把低分辨率图像变高分辨率：
- 输入：低分辨率图像（CNN 特征提取）
- 输出：高分辨率图像
- 训练数据：低/高分辨率图像对
- 损失函数：L2 + 感知损失（VGG）+ 对抗损失

### Q30. 模型：Real-ESRGAN？

A: Real-ESRGAN：盲超分辨率（不看降质类型）：
- 实战效果好
- 部署成熟
- 用于老片修复 + 实时超分

### Q31. AI 插帧？

A: 估算中间帧：
- 光流法：基于运动估算
- 神经网络：直接生成
- 模型：RIFE / FILM / DAIN

## 🏢 八、系统设计

### Q32. 短视频上传系统设计？

A:
1. **客户端**：分片 + 断点续传
2. **接收服务**：分配 uploadId
3. **分片上传**：并行上传分片
4. **合并**：校验 + 转存 OSS
5. **转码**：分发到转码集群
6. **AI 处理**：审核 + 封面
7. **媒体库**：写入数据库 + 索引
8. **CDN 预热**：回源 + 缓存

### Q33. 如何设计实时直播系统？

```
1. 推流服务（接收 RTMP / WebRTC）
2. 转码集群（多分辨率）
3. CDN 分发（200+ 节点）
4. 录制集群（自动录制）
5. 审核服务（实时）
6. IM 服务（弹幕 / 互动）
7. 数据统计（Kafka 流式）
```

### Q34. 海量录像存储？

A:
1. **存储分层**：热 / 温 / 冷
2. **纠删码**：Erasure Coding (10 + 4)
3. **HDFS / 对象存储**：分布式
4. **动态码率**：VFR
5. **定期归档**：Glacier
6. **智能降级**：无人时降低录制

### Q35. CDN 调度策略？

A:
- **地理调度**：用户 IP 决定最近 PoP
- **网络调度**：BGP 路由质量
- **性能调度**：实时探测延迟
- **成本调度**：按权重选 CDN
- **冗余调度**：失败自动切换

## ⚙️ 九、容器格式

### Q36. MP4 vs MKV vs AVI？

| 容器 | 流格式 | 用途 |
| --- | --- | --- |
| **MP4** | H.264/H.265 + AAC | 通用、流媒体 |
| **MKV** | 多流多轨 | 影视 |
| **AVI** | 老格式 | 过去 |
| **WebM** | VP8/VP9 + Opus | Web |
| **TS** | MPEG-TS | 广播 |
| **FLV** | H.264 + AAC | RTMP |

### Q37. 怎么切割 MP4？

A:
- **断点续传式切片**：在 mp4 moov 中插入 seek 索引，不重新编解码
- **重新封装**：用 ffmpeg -c copy 复制格式

## 🎯 十、OpenGL / GPU

### Q38. YUV → RGB 转换？

A: 通过 BT.601 / BT.709 / BT.2020 矩阵：

```
R = 1.164 * (Y - 16) + 1.793 * (V - 128)
G = 1.164 * (Y - 16) - 0.213 * (U - 128) - 0.533 * (V - 128)
B = 1.164 * (Y - 16) + 2.112 * (U - 128)
```

GPU 上 Shader 实现。

### Q39. Shader 性能优化？

A:
- 减少纹理采样次数
- 避免 dependent texture
- use mipmap
- 减少分支
- 用 LUT 代替复杂运算
- OpenGL ES 3.0+ 特性

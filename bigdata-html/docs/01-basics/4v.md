# 大数据 4V 特征

## 1. 大数据定义

大数据（Big Data）= 无法用传统数据库工具在合理时间内处理的数据集。

## 2. 4V 特征

### Volume（体量大）

```
MB → GB → TB → PB → EB → ZB

2010: 1-10 TB（企业级）
2020: 100 TB-10 PB（互联网）
2025: 1-100 PB（大型互联网）
2030: 1+ EB（预测）

案例：
- Google 每天处理 100+ PB
- Facebook 每天新增 4 PB 数据
- 单个望远镜（LSST）每晚产生 20 TB
```

### Velocity（速度快）

```
实时数据流：
- 金融交易：毫秒级决策
- IoT 传感器：每秒百万级
- 监控告警：秒级异常检测
- 推荐系统：100ms 内响应

两批处理方式：
- 批处理（Batch）：MapReduce / Spark SQL / Hive
- 流处理（Stream）：Kafka Streams / Flink
```

### Variety（多样）

```
结构化（20%）：关系型 DB / Excel / CSV
半结构化（30%）：JSON / XML / Log / HTML
非结构化（50%）：图像 / 视频 / 音频 / PDF

存储差异：
- 结构化：行式（Parquet / ORC）
- 半结构化：JSON / XML Hive
- 非结构化：对象存储（S3 / OSS）+ 元数据
```

### Value（价值）

```
数据金字塔：
  数据 → 信息 → 知识 → 洞察 → 决策

数据 ≠ 价值
  - 挖掘：统计 / ML / 业务理解
  - 清洗：脏数据变可信
  - 应用：业务问题 → 业务价值

经典场景：
  - 推荐系统（1% 转化提升 = 千万营收）
  - 风控（1% 坏账率降低 = 千万节约）
  - 运营优化（1% 效率 = 千万成本）
```

## 3. 大数据 vs 传统数据

| | 传统 DB | 大数据 |
|------|--------|--------|
| 数据量 | GB-TB | PB-EB |
| 速度 | 实时 | 实时 + 批 |
| 多样性 | 结构化 | 半/非结构化 |
| 价值 | 报表 | 洞察 + ML |
| 工具 | Oracle / MySQL | Hadoop / Spark / Flink |

## 4. 数据生命周期

```
原始 → 采集 → 存储 → 处理 → 分析 → 消费
  IoT   Kafka   HDFS   Spark   BI    报表
  App   Flink   S3    Flink   API
                  Iceberg  ML
```

## 5. 大数据技术栈全景

```
数据采集
  Flume / Kafka Connect / Logstash / Sqoop
       ↓
消息队列
  Kafka / Pulsar / RocketMQ
       ↓
存储层
  HDFS / S3 / OSS / Hudi / Iceberg
       ↓
批处理
  MapReduce / Spark SQL / Hive / Pig
       ↓
流处理
  Spark Streaming / Flink / Kafka Streams
       ↓
服务层
  Presto / Trino / HiveServer / Impala
       ↓
应用
  BI / 推荐 / 风控 / 搜索 / 画像
```

## 6. 大数据 vs 数据中台 vs 数据湖

```
大数据：技术体系（存储 + 计算）
数据中台：业务体系（一站式数据服务）
数据湖：存储范式（原始 + 灵活分析）
Lakehouse：数据湖 + 数据仓库（统一）
```

**关系**：大数据是底层技术，数据中台是上层业务抽象，数据湖是存储形态。

## 7. 实战选型

| 场景 | 选 |
|------|-----|
| 离线批处理 | Spark SQL + Hive |
| 实时流处理 | Flink + Kafka |
| 实时+离线融合 | Flink + Iceberg |
| BI 报表 | ClickHouse / Doris |
| 数据湖 | Delta Lake / Iceberg |
| 数据仓库 | Snowflake / Redshift |
| 资源有限 | Hadoop + Spark（自建） |
| 资源充足 | 云服务（阿里云 MaxCompute / AWS EMR） |

## 8. 性能指标

| 指标 | 大数据 | 传统 |
|------|--------|------|
| 吞吐量 | TB/hour | GB/hour |
| 延迟 | 秒-分钟 | 毫秒 |
| 数据量 | PB | TB |
| 并发 | 1000+ | 100 |

## 9. 关键挑战

1. 一致性（CAP 选型）
2. 扩展性（水平扩展）
3. 容错性（节点故障）
4. 延迟（实时 vs 批）
5. 成本（存储 + 计算）

# 📡 TCP/IP 四层模型

> 互联网实际使用的协议族模型，比 OSI 更精简。

## 🎯 四层结构

```
┌────────────────────────────────────────────┐
│           应用层 (Application)              │
│  HTTP / DNS / FTP / SMTP / SSH / MQTT      │
├────────────────────────────────────────────┤
│           传输层 (Transport)                │
│           TCP / UDP / SCTP                  │
├────────────────────────────────────────────┤
│           网际层 (Internet)                 │
│      IP / ICMP / ARP / IGMP                │
├────────────────────────────────────────────┤
│         网络接口层 (Link / Network Access)   │
│   Ethernet / WiFi / PPP / ATM / 帧中继      │
└────────────────────────────────────────────┘
```

## 📋 各层职责

| 层 | 名称 | 数据单位 | 核心协议 | 关键设备 |
|---|---|---|---|---|
| 4 | 应用层 | 报文/数据 | HTTP, DNS, TLS, FTP | 网关、代理 |
| 3 | 传输层 | 段（TCP）/数据报（UDP）| TCP, UDP | 负载均衡器 |
| 2 | 网际层 | IP 包 | IP, ICMP, ARP | 路由器 |
| 1 | 网络接口层 | 帧 | Ethernet, WiFi, PPP | 交换机、网卡 |

## 🔄 报文封装格式

### 应用层 → 传输层

```
TCP 头部                应用数据
┌─────────────────┐   ┌──────────────┐
│ Source Port     │   │              │
│ Dest Port       │   │   HTTP 请求   │
│ Seq Number      │   │   报文       │
│ Ack Number      │   │              │
│ Flags / Window  │   │              │
└─────────────────┘   └──────────────┘
         ↓ TCP Segment
```

### 传输层 → 网际层

```
IP 头部                  TCP Segment
┌─────────────────┐   ┌─────────────────┐
│ Version/IHL     │   │ TCP 头 + 数据    │
│ TTL             │   │                 │
│ Source IP       │   │                 │
│ Dest IP         │   │                 │
│ Protocol        │   │                 │
└─────────────────┘   └─────────────────┘
         ↓ IP Packet
```

### 网际层 → 网络接口层

```
以太网帧头                IP Packet              帧尾
┌──────────────┐       ┌──────────────┐       ┌────────┐
│ Dest MAC     │       │ IP 头 + TCP    │       │ FCS    │
│ Src MAC      │       │ 头 + 数据     │       │ 校验   │
│ EtherType    │       │              │       │        │
└──────────────┘       └──────────────┘       └────────┘
         ↓ Ethernet Frame
```

## 📊 OSI 与 TCP/IP 对应

```
OSI 层                TCP/IP 层          协议示例
─────────────────────────────────────────────────
应用层 (7)  ──┐
表示层 (6)  ──┼──→ 应用层          HTTP/DNS/FTP
会话层 (5)  ──┘
                     ───────────
传输层 (4)  ──────→  传输层          TCP/UDP
                     ───────────
网络层 (3)  ──────→  网际层          IP/ICMP/ARP
                     ───────────
数据链路层 (2)─┐
              ├──→ 网络接口层       Ethernet/WiFi
物理层 (1)  ──┘
```

## 🎯 关键协议对照

| 协议 | 所在层 | 功能 |
|---|---|---|
| HTTP | 应用层 | 超文本传输 |
| DNS | 应用层 | 域名解析 |
| TLS/SSL | 表示层（应用层下）| 传输加密 |
| TCP | 传输层 | 可靠传输 |
| UDP | 传输层 | 无连接传输 |
| IP | 网际层 | 网络寻址 |
| ICMP | 网际层 | 错误报告（ping）|
| ARP | 网际层 | IP→MAC 映射 |
| PPP | 网络接口层 | 点到点连接 |
| Ethernet | 网络接口层 | 局域网帧格式 |

## ⚡ TCP/IP 特点

| 优点 | 缺点 |
|---|---|
| 简单实用 | 层次不够清晰 |
| 协议标准化 | 安全设计滞后 |
| 跨平台、跨网络 | 早期协议无认证加密 |
| 事实标准 | 模型层次少 |

## 🛠️ 实际应用：浏览器输入 URL

```
1. 应用层：浏览器解析 URL，发起 HTTP 请求
2. 传输层：建立 TCP 连接（三次握手），端口 443
3. 网际层：通过 DNS 获取 IP，加上 IP 头
4. 网络接口层：ARP 解析 MAC，加上以太网头
5. 物理层：转换为电信号/光信号传输
   ───── 网络传输 ─────
6. 接收端反向解封装，响应内容原路返回
```

## 🎓 面试高频问题

| 问题 | 关键点 |
|---|---|
| TCP/IP 哪四层？| 应用、传输、网际、网络接口 |
| TCP 在哪层？| 传输层 |
| IP 在哪层？| 网际层 |
| 与 OSI 的区别？| TCP/IP 是 4 层实际标准，OSI 是 7 层理论模型 |

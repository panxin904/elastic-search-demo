# 3-2-1 备份原则 — 数据保护的黄金法则

> <span class="kg-badge kg-badge--backup">备份快照</span>
> 3 份副本 · 2 种介质 · 1 份异地

**3-2-1 规则**是数据保护的事实标准：

- **3 份**数据副本（1 原始 + 2 备份）
- **2 种**存储介质（防介质级故障）
- **1 份**异地（防灾难级故障）

## 1. 3-2-1 的由来

源自 2000 年代摄影业：

- 3 份：照片重要
- 2 种介质：照片放不同物理载体
- 1 份异地：防止地震 / 火灾

**今天**依然适用 —— 但需要扩展到 **3-2-1-1-0** 等加强版。

## 2. 经典 3-2-1

```text
主数据     →  本地备份盘 (RAID-1)     →  异地备份 (云 / 异地机房)
   1              2                          3

3 份：原始 + RAID 镜像 + 异地
2 种介质：SSD + 云
1 份异地：异地机房或云
```

## 3. 3-2-1-1-0（增强版）

```
3 份数据
2 种介质
1 份异地
1 份离线（air-gap，防勒索软件）
0 错误（恢复演练）
```

**关键**：勒索软件让在线备份失效 → 必须有**离线副本**。

## 4. 实战：企业 3-2-1 配置

```text
[生产]                    [本地备份]              [异地备份]
  - 应用服务器                - 备份服务器             - 异地机房
  - 数据库（RAID-10）          - Borg / restic         - 异地复制
                              - 本地 ZFS 快照          - 异地对象存储
                              
[离线备份]
  - 每周一次手动镜像到外部硬盘
  - 放到保险柜 / 异地柜
```

## 5. 实战：个人 3-2-1

```text
[本地]
  - 1：NAS RAID-1
  - 2：本地 USB 硬盘

[异地]
  - 3：云存储（OSS / S3 / B2）

工具：restic 加密后 push 到 S3
```

## 6. RTO / RPO

| 等级 | RTO（恢复时间） | RPO（数据丢失） | 实现 |
|------|----------------|----------------|------|
| 青铜 | 24 小时 | 24 小时 | 每天异地备份 |
| 白银 | 4 小时 | 1 小时 | 每小时快照 + 异地 |
| 黄金 | 10 分钟 | 1 分钟 | 实时复制 + 异地 |
| 钻石 | 0 | 0 | 多 AZ 同步 |

## 7. 异地备份的实现

### 7.1 同步 / 异步复制

```bash
# 异步（批处理）
rsync -az /data/ user@backup-server:/backup/

# 实时同步
drbd                  # 块设备同步
glusterfs geo-replication
lsyncd + rsync        # inotify + rsync
```

### 7.2 对象存储（云）

```bash
# 异地对象存储
restic -r s3:s3.us-east-1.amazonaws.com/backup backup /data
restic -r s3:s3.eu-west-1.amazonaws.com/backup copy ...
```

## 8. 离线备份（air-gap）

```text
防勒索软件 = 必须有"拔掉网线也能恢复"的备份

实现：
1. 定期手动备份到 USB 硬盘
2. 异地柜（物理隔离）
3. 磁带备份（LTO）
4. WORM 存储（OSS Object Lock）
5. S3 Glacier Deep Archive
```

```bash
# 自动 mount / umount USB 备份
mount /dev/sdc1 /mnt/usb
borg create /mnt/usb/repo::backup-$(date +%F) /data
umount /mnt/usb
# 物理拔掉 USB
```

## 9. 验证：恢复演练

**数据没验证 = 没备份**！

```bash
#!/bin/bash
# 月度恢复演练脚本

# 1. 随机抽 5 个文件
FILES=$(restic -r /backup/repo ls latest | shuf -n 5)

for FILE in $FILES; do
    # 2. 恢复到临时目录
    restic -r /backup/repo restore latest \
        --target /tmp/restore \
        --include "$FILE"

    # 3. 校验（hash 对比）
    ORIG_HASH=$(sha256sum /path/to/orig/$FILE | awk '{print $1}')
    BACK_HASH=$(sha256sum /tmp/restore/$FILE | awk '{print $1}')

    if [ "$ORIG_HASH" != "$BACK_HASH" ]; then
        echo "FAIL: $FILE"
        exit 1
    fi
done

echo "PASS: 5 files verified"
```

## 10. 监控备份状态

```yaml
# Prometheus 抓取
- job_name: restic_backup
  static_configs:
    - targets: ['node-exporter:9100']
  metrics_path: /backup-metrics
```

```bash
# 自定义告警
#!/bin/bash
LAST=$(restic -r /backup/repo snapshots --json | jq -r '.[-1].time')
AGE=$(($(date +%s) - $(date -d "$LAST" +%s)))
if [ $AGE -gt 86400 ]; then
    echo "WARNING: Last backup is $AGE seconds old"
    alert
fi
```

## 11. 常见误区

| 误区 | 后果 |
|------|------|
| "备份完了就稳了" | 没演练恢复 = 真正出事时打不开 |
| "快照就够了" | 快照同存储，**介质故障一起挂** |
| "3-2-1 太贵" | 数据丢失的代价更贵 |
| "用异地同步就够了" | 勒索软件会**同步感染**异地 |
| "磁带备份落后" | 磁带是最便宜的离线存储 |

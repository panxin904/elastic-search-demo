# 重点关注

开发中容易踩坑、影响系统质量和稳定性的 12 个关键领域，是每个 Java Web 开发者的必修课。

## 关注维度

| 维度 | 要点 | 出了问题会怎样 |
|---|---|---|
| **规范类** | 异常处理、日志、参数校验、代码规范 | 线上排查困难、代码难以维护 |
| **数据类** | 事务管理、缓存策略、数据脱敏 | 数据错乱、缓存雪崩、隐私泄露 |
| **稳定性类** | 接口幂等、限流熔断、并发控制 | 重复扣款、服务雪崩、数据错乱 |
| **质量类** | 安全实践、性能优化 | SQL注入、接口超时、系统崩溃 |

## 核心关注点

### 规范基础

<div class="kg-note kg-note-tip">
**四件套必须做好**：异常处理 → 日志规范 → 参数校验 → 代码规范。这四项做不好，后面一切都免谈。
</div>

| 关注点 | 核心原则 |
|---|---|
| [异常处理](/03-practice/exception-handling) | 统一异常拦截、业务异常可追溯、不吞异常 |
| [日志规范](/03-practice/logging) | 分级打印、关键节点有日志、敏感信息脱敏、traceId |
| [参数校验](/03-practice/validation) | Controller层入口校验、@Valid统一拦截、不信任任何输入 |
| [代码规范](/03-practice/code-style) | 命名规范、职责单一、注释关键处、拆分解耦 |

### 数据安全

| 关注点 | 核心原则 |
|---|---|
| [事务管理](/03-practice/transaction) | 理解传播行为与隔离级别、避免长事务、注意自调用失效 |
| [缓存策略](/03-practice/cache-strategy) | 先查缓存再查DB、设置过期时间、应对穿透/击穿/雪崩 |
| [数据脱敏](/03-practice/data-masking) | 手机号/身份证中间打*、序列化时统一拦截 |
| [安全实践](/03-practice/security) | 防SQL注入/XSS/CSRF、JWT安全使用、权限最小化 |

### 稳定性保障

| 关注点 | 核心原则 |
|---|---|
| [接口幂等](/03-practice/idempotency) | Token机制/唯一索引/分布式锁，防止重复提交 |
| [限流熔断](/03-practice/rate-limiting) | Sentinel/Guava限流，下游慢就熔断降级 |
| [并发控制](/03-practice/concurrency) | 共享资源加锁、乐观锁版本号、ThreadLocal传递上下文 |
| [性能优化](/03-practice/performance) | SQL优化/SQL监控、连接池调优、异步化、减少锁竞争 |

## 优先级矩阵

```
           │ 出问题影响小  │ 出问题影响大
───────────┼──────────────┼──────────────
容易实现    │  代码规范     │  异常处理
           │  日志规范     │  参数校验
───────────┼──────────────┼──────────────
实现较难    │  数据脱敏     │  事务管理 🔥
           │              │  缓存策略 🔥
           │              │  接口幂等 🔥
           │              │  安全实践 🔥
           │              │  限流熔断 🔥
           │              │  并发控制 🔥
```

> 🔥 = 高优先级，必须花时间搞懂

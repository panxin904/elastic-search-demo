# 技术方案

在理解需求之后，需要产出技术方案，明确怎么做、用什么技术、花多少时间。

## 技术方案内容

### 1. 技术选型

| 层面 | 选项 | 选择理由 |
|---|---|---|
| 框架 | Spring Boot 2.x / 3.x | 公司技术栈统一 |
| ORM | MyBatis-Plus | SQL 灵活、分页方便 |
| 数据库 | MySQL 8.0 | 数据量合适、团队熟悉 |
| 缓存 | Redis | 热点数据缓存、分布式锁 |
| 消息队列 | RabbitMQ | 异步解耦场景 |

<div class="kg-note kg-note-tip">
<strong>选型原则</strong>：能用简单的就不用复杂的；团队会的优先；社区活跃的优先；非必要不引入新技术。
</div>

### 2. 架构设计

```
┌─────────────────────────────────────────┐
│              前端 (Vue/React)            │
└─────────────────┬───────────────────────┘
                  │ HTTP/REST
┌─────────────────┴───────────────────────┐
│        Controller 层 (API入口)           │
├─────────────────────────────────────────┤
│        Service 层 (业务逻辑)             │
├─────────────────────────────────────────┤
│        DAO/Mapper 层 (数据访问)          │
├─────────────────────────────────────────┤
│     MySQL         Redis        MQ       │
└─────────────────────────────────────────┘
```

### 3. 模块划分

```java
com.example.project
├── controller/     // REST 接口
├── service/        // 业务逻辑
│   └── impl/
├── mapper/         // MyBatis Mapper
├── entity/         // 实体类
├── dto/            // 数据传输对象
├── vo/             // 视图对象
├── config/         // 配置类
├── common/         // 公共类（异常、响应、工具）
└── enums/          // 枚举
```

### 4. 数据库设计要点

- ER 图标注核心实体和关系
- 索引设计：高频查询字段、唯一约束字段
- 分表策略（按时间/按ID取模）
- 冷热数据分离策略

### 5. 接口设计概要

列出所有接口的 URL、方法、入参、出参：

| 接口 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 创建订单 | POST | /api/orders | 用户下单 |
| 查询订单 | GET | /api/orders/{id} | 按ID查详情 |
| 订单列表 | GET | /api/orders | 分页查询 |

### 6. 风险评估

| 风险 | 等级 | 应对措施 |
|---|---|---|
| 第三方接口不稳定 | 高 | 超时+重试+降级 |
| 数据库性能瓶颈 | 中 | 索引优化+读写分离 |
| 并发库存超卖 | 高 | Redis分布式锁 |

### 7. 排期拆分

```
第一周：数据库设计 + 基础 CRUD 接口
第二周：核心业务逻辑 + 单元测试
第三周：联调 + 集成测试
第四周：上线 + 监控
```

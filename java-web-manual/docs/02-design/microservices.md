# 微服务架构

微服务将单体应用拆分为一组独立部署的小服务，每个服务围绕特定业务能力构建。

## 微服务核心组件

```
┌──────────┐  ┌──────────┐  ┌──────────┐
│ 订单服务  │  │ 用户服务  │  │ 商品服务  │
└─────┬────┘  └─────┬────┘  └─────┬────┘
      │             │             │
      └─────────────┼─────────────┘
                    │
    ┌───────────────┼───────────────┐
    │               │               │
┌───┴───┐     ┌─────┴──────┐  ┌───┴────┐
│Nacos  │     │  Gateway   │  │Sentinel│
│注册中心│     │  网关      │  │ 限流   │
└───────┘     └────────────┘  └────────┘
```

## Spring Cloud Alibaba 栈

| 组件 | 功能 |
|---|---|
| Nacos | 注册中心 + 配置中心 |
| Sentinel | 流量控制、熔断降级 |
| Seata | 分布式事务 |
| Gateway | API 网关 |
| RocketMQ | 消息队列 |

## 拆分原则

| 原则 | 说明 |
|---|---|
| 单一职责 | 一个服务只做一件事 |
| 高内聚低耦合 | 服务内部紧密，服务间松散 |
| 数据独立性 | 每个服务有独立数据库 |
| 渐进式拆分 | 从核心业务开始，逐步拆 |

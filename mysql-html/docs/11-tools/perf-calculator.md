# 🧮 MySQL 性能计算器

## 🎯 计算器说明

### 🌳 B+Tree 高度

根据**数据量 + 扇出（fanout）** 估算 B+Tree 索引树的高度。

**应用场景：**
- 评估索引效率（树高 = 磁盘 IO 次数）
- 决定主键宽度（主键越小，扇出越大）
- 优化分片键选择

**示例：**
- 1 亿行 + 扇出 200 → 树高 3 层 → 3 次 IO
- 10 亿行 + 扇出 200 → 树高 4 层 → 4 次 IO
- 100 亿行 + 扇出 200 → 树高 5 层 → 5 次 IO（考虑分库分表）

### 💾 索引大小估算

根据**数据量 + 字段宽度** 估算索引占用的磁盘空间。

**应用场景：**
- 容量规划
- 决定是否使用前缀索引
- 评估索引对写入性能的影响

### 🧠 Buffer Pool 估算

推荐 **Buffer Pool 大小**（一般设为物理内存的 60-80%）。

**应用场景：**
- 服务器选型
- my.cnf 配置
- 评估缓存命中率

**经验值：**
- 缓冲池命中率应 > 99%
- 如果 < 95%，需要增大 buffer_pool_size

### 📊 QPS 容量估算

根据**磁盘 IOPS** 估算最大 QPS 容量。

**应用场景：**
- 容量规划
- 硬件选型
- 性能瓶颈定位

**示例：**
- HDD（~1000 IOPS）→ 几百 QPS
- SATA SSD（~50000 IOPS）→ 几万 QPS
- NVMe SSD（~500000 IOPS）→ 几十万 QPS
